# From contract to code

One row per block. The complete example is `assets/example/icon-button/`.

| Contract block | In the code |
| --- | --- |
| `name`, `id`, `version` | `export function <name>`, folder `<id>/`, comment `/** @contract <name>@<version> */` |
| `props[]` | `export interface <name>Props`: same name, type, `?` if it has a `default`, no `?` if `required`. Defaults in the destructuring |
| `props[].type` with `'a' \| 'b'` | Literal union, identical |
| `props[].name` with hyphen (`aria-label`) | Quoted key in the type and alias when destructuring: `'aria-label': ariaLabel` |
| `props[]` of type `ReactNode` with `slot` | Prop of type `ReactNode` or `children`, per `anatomy.<part>.slot` |
| `semantics.element` | HTML element of the root part (`button`, `a`, `div`…) |
| `semantics.refTarget` | `ref` on that part. React 19: normal `ref` prop (`ref?: Ref<HTMLButtonElement>`). React 18: `forwardRef` |
| `anatomy.<part>` | `data-part="<key>"` on the element. `element: "css"` has no element (focus, underline) |
| `anatomy.<part>.content.prop` | Rendered with that prop (`children`) |
| `states.native` | CSS: `:hover`, `:focus-visible`, `:active` (with `:not(:disabled)` on hover/active) |
| `states.controlled[]` | Props. Whatever `aria` says: `aria-busy`, `aria-disabled`, native `disabled` attribute… |
| Variant props (`variant`, `color`, `size`…) | `data-variant`, `data-color`, `data-size` on the root element |
| Boolean props that change style (`highContrast`, `loading`) | `data-high-contrast={highContrast \|\| undefined}` (attribute present or absent, never `="false"`) |
| `tokens.bindings`, `tokens.scales` | Block generated by `gen-css.mjs`. `{color.step}` templates are expanded per value |
| `layout.height/width` | If there is a token (`tokens.space.button-height-N`), the generated block already provides it. If not, the contract's value in CSS |
| `layout.iconSize`, `layout.autoLayout` | Hand-written CSS with the contract's values |
| `events[]` | Props `onPress`, etc. They do not fire if `blockedWhen` includes an active state |
| `behavior.loading` | `loading` → `aria-busy`, spinner instead of content, emits no events, same size |
| `behavior.motion[]` | `transition` only on the indicated property; `@media (prefers-reduced-motion: reduce)` → instant |
| `behavior.responsive[]` | `@media` with the indicated breakpoint. If it is a loose value, it is a `needsReview` |
| `composition.forbiddenChildren` | Comment/type; the contract rules: do not render them inside |
| `composition.nestedComponents` | Import the existing component and use it with its `fixedProps` |
| `a11y` | Accessible name, keyboard, visible focus, minimum target. `aria-label` is mandatory if the contract requires it (required prop) |
| `meta.needsReview` | What affects you: ask, or `TODO(contract): …` and add it to the summary list |

## What `gen-css.mjs` does and does not do

**Translates** these `tokens.bindings` keys: `background`, `text`, `iconColor`, `border`, `borderWidth`, `shadow`, `opacity`, `height`, `size`, `paddingX`, `gap`, `radius`, `textStyle`, and Link's `underline`. Organized by `base`, `bySize`, `byVariant.<v>.<default|hover|active>`, `byHighContrast`, `byState.disabled`.

**Rules of the CSS it produces:**
- Attributes go inside `:where(...)`, so all state rules have the same specificity and order decides (base → size → variant → high contrast → disabled).
- `hover` and `active` carry `:not(:disabled)`; `disabled` goes with `:disabled`.
- A `null` value in a scale (`surface` in neutral) is translated as "none": `transparent` for background and border, `none` for shadow.
- Numeric `borderWidth` → `Npx` and `border-style: solid`.
- It does not generate the focus ring (`focusRing*`): write it by hand from `base.focusRingInner/Outer`.

**Does not translate** (shown in the "untranslated keys" warning, you write them from the contract): contracts of fields with their own states, such as `placeholder`, `filled`, `readOnly`, `checked`, `indeterminate`, `track`, `thumb`, `labelColor`, `iconContainerPadding`, `inputTextStyle`. TextField, Checkbox, RadioGroup and Switch fall here. The verifier does check them (which variables you use, that they exist, that there are no loose values).

When writing those parts by hand: use the contract's keys as a guide to **which token goes on which property** and look at `byState` / `byVariant` to know in which state. If the contract does not say the CSS property, do not guess: `TODO(contract)`.

## Patterns

**Root element with attributes**

```tsx
<button
  ref={ref}
  className={styles.root}
  data-part="root"
  data-variant={variant}
  data-color={color}
  data-size={size}
  data-high-contrast={highContrast || undefined}
  disabled={disabled}
  aria-busy={loading || undefined}
>
```

**Optional slot** (`min: 0`): render the part only if there is content, with its `data-part`.

**Radix (complex behavior)**

```tsx
"use client";
import { Checkbox as RadixCheckbox } from 'radix-ui';
// The indicator and the state come from Radix (data-state="checked|unchecked|indeterminate").
// Styles: selectors on [data-state="…"] and our variant data-* attributes.
```

The contract gives the props and tokens; Radix provides focus, keyboard and ARIA. If Radix sets `data-state`, use it in the CSS instead of inventing another attribute, and verify the contract does not ask for another.

**Icons:** only those in the registry, from the project's generated `icons.ts`, through the `Icon` component. The size is set by the parent's CSS per `layout.iconSize`.

**Documentation:** if the project generates `<id>.md` from the contract, do it with: description, do's and don'ts, props table, states, anatomy, tokens and accessibility, **without adding anything that is not in the contract**.
